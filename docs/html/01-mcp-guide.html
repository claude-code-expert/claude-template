MCP 설치·구성 가이드

강의 1편 · 대상 Claude Code 사용자 · 명령·설정 문법은 공식 문서(anthropics/claude-code) 기준으로 확인함

개념MCP란 무엇인가

MCP(Model Context Protocol)는 Claude 같은 모델과 외부 도구·데이터 소스를 잇는 개방 규격이다. 모델 자체는 파일을 못 읽고 네트워크도 못 탄다. MCP 서버가 그 능력을 "도구(tool)"로 노출하면, Claude가 대화 중에 그 도구를 호출한다.

비유하자면 USB-C 같은 것이다. 서버마다 붙이는 방식이 제각각이면 관리가 안 되니, 연결 규격 하나로 통일해 두고 서버만 갈아 끼운다. 문서 조회 서버, 브라우저 자동화 서버, 사내 DB 서버를 같은 방식으로 등록한다.

언제 붙이나 / 언제 안 붙이나

붙일 때안 붙일 때
최신 라이브러리 문서 조회모델이 이미 잘 아는 일반 개념 설명
실제 브라우저로 E2E 확인단순 코드 한 줄 수정
사내 시스템·DB·API 연동도구 없이 파일 편집으로 끝나는 작업
판단 기준

서버를 많이 붙일수록 각 도구 설명이 컨텍스트를 먹고 선택지가 늘어 오히려 느려진다. "이 서버가 없으면 못 하는 일"이 있을 때만 붙인다. 개발용 최소 구성은 06번에서 3종으로 좁힌다.

범위스코프 — 어디까지 보이게 할 것인가

같은 서버라도 스코프에 따라 노출 범위가 다르다. 등록할 때 --scope로 정한다.

스코프범위저장 위치
local나 · 이 프로젝트에서만 (기본값)내 사용자 설정 안의 프로젝트별 항목
project이 프로젝트를 여는 모두.mcp.json (레포에 커밋)
user나 · 내 모든 프로젝트사용자 전역 설정
주의

project 스코프(.mcp.json)는 레포에 커밋된다. API 키·토큰을 값에 직접 박지 말 것. 아래 04번처럼 ${ENV_VAR} 확장으로 빼내고, 실제 값은 각자 환경변수에 둔다.

방법 A.mcp.json 직접 작성

프로젝트 루트에 .mcp.json을 만들고 최상위 mcpServers 아래에 서버를 나열한다. Claude Code가 그 프로젝트를 열 때 자동으로 읽는다.

stdio 서버 — 로컬 프로세스 (npx 배포판)

대부분의 오픈소스 MCP는 npm 패키지로 배포된다. npx로 실행하는 게 표준이다.

.mcp.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path"]
    }
  }
}

http 서버 — 원격 엔드포인트 + 토큰

REST/HTTP로 붙는 서버는 type: "http"와 url을 준다. 인증 헤더는 환경변수로 뺀다.

.mcp.json
{
  "mcpServers": {
    "api": {
      "type": "http",
      "url": "https://api.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${API_TOKEN}"
      }
    }
  }
}

환경변수 확장

값 안에서 ${VAR}로 환경변수를 끌어온다. 기본값은 ${VAR:-default} 형태로 준다. 비밀값을 파일에서 분리하는 핵심 장치다.

.mcp.json — env 블록
{
  "mcpServers": {
    "db": {
      "command": "npx",
      "args": ["-y", "some-db-mcp"],
      "env": {
        "DATABASE_URL": "${DB_URL}",
        "LOG_LEVEL": "${LOG_LEVEL:-info}"
      }
    }
  }
}

방법 Bclaude mcp add CLI

JSON을 손으로 안 짜고 명령 한 줄로 등록한다. 세 가지 형태가 있다.

① 대화형 마법사

인자 없이 실행하면 단계별로 물어본다. 처음이라면 이게 제일 안전하다.

터미널
claude mcp add

② 인자형 — stdio 서버

-- 뒤에 실제 실행 명령을 적는다. --는 Claude 플래그와 서버 명령을 가르는 구분선이다.

터미널
# 형식: claude mcp add [--scope ..] [--env K=V] <이름> -- <명령> [인자...]
claude mcp add --scope project sequential-thinking \
  -- npx -y @modelcontextprotocol/server-sequential-thinking

③ 인자형 — http 서버

터미널
claude mcp add --transport http context7 https://mcp.context7.com/mcp

④ JSON 통째로 — add-json

README에 나온 설정 블록을 그대로 넘길 때.

터미널
claude mcp add-json playwright '{"command":"npx","args":["-y","@playwright/mcp@latest"]}'

등록 확인

  • claude mcp list — 등록된 서버와 연결 상태를 CLI에서 확인
  • 세션 안에서 /mcp — 현재 붙은 서버·도구 목록과 상태를 확인
팁

서버가 list엔 뜨는데 도구가 안 보이면 대개 명령·경로·토큰 문제다. claude mcp list의 상태 표시와 서버 실행 명령을 먼저 의심한다.

실전개발에 필요한 최소 MCP 3종

이 템플릿 레포가 이미 큐레이션한 구성이다. 문서·사고·브라우저 세 축이면 대부분의 개발 작업을 덮는다. 각 서버의 자세한 사용법은 레포의 .claude/mcp/*.md에 있다.

서버를 어디서 찾나

필요한 서버가 있는지 먼저 레지스트리에서 검색한다. 설치 명령·설정 블록을 그대로 제공한다.

  • Smithery — MCP 서버 검색·원클릭 설치. 클라이언트별 설치 명령을 생성해준다.
  • MCP Market (한국어) — 카테고리별 서버 목록과 설정 예시를 한국어로 제공.

레지스트리에서 고른 서버는 아래 흐름으로 붙인다. 제공된 설치 명령은 07번 프롬프트로 최신 여부를 한 번 더 검증하면 안전하다.

context7 — 최신 공식 문서 조회

라이브러리 API·설정·마이그레이션을 학습 데이터가 아니라 최신 문서에서 가져온다. 잘 아는 프레임워크라도 버전이 바뀌었을 수 있으니 웹 검색보다 우선한다.

터미널
claude mcp add --transport http context7 https://mcp.context7.com/mcp
# 또는 stdio: claude mcp add context7 -- npx -y @upstash/context7-mcp

sequential-thinking — 다단계 사고

설계·디버깅·리팩터링처럼 계획을 세우고 도중에 방향을 고쳐야 하는 작업에서 생각을 단계로 쪼갠다. 단순 조회엔 쓰지 않는다.

터미널
claude mcp add sequential-thinking \
  -- npx -y @modelcontextprotocol/server-sequential-thinking

playwright — 실제 브라우저 구동

E2E 확인, 폼 입력, 스크린샷, 콘솔·네트워크 검사. 접근성 트리(snapshot) 기반으로 요소를 잡으므로 좌표가 아니라 ref로 조작한다.

터미널
claude mcp add playwright -- npx -y @playwright/mcp@latest

npx 직접 설치 형태와 플랫폼별 변형

공식 저장소(예: modelcontextprotocol/servers)는 claude mcp add 없이 설정 블록에 npx를 직접 적는 형태와, Windows·docker 변형을 함께 보여준다. .mcp.json에 넣는 값은 위 통합 설정의 command/args와 동일하다 — 다음은 그 원형과 변형이다.

sequential-thinking — 원형·변형
# 직접 실행 (설정의 command:"npx", args:[...] 가 이것과 같다)
npx -y @modelcontextprotocol/server-sequential-thinking

# 순수 Windows에서 npx가 command 로 안 먹으면 cmd 로 감싼다
#   "command": "cmd", "args": ["/c","npx","-y","@modelcontextprotocol/server-sequential-thinking"]

# docker 대안
#   "command": "docker", "args": ["run","--rm","-i","mcp/sequentialthinking"]
플랫폼

WSL2·macOS·리눅스에서는 command: "npx" 그대로 쓴다. cmd /c 래핑은 네이티브 Windows 클라이언트에서 npx를 못 찾을 때만 필요하다. docker 형태는 Node 없이 컨테이너로 돌릴 때.

확인 습관

패키지명·전송 방식은 서버마다 바뀐다. 붙이기 전 각 서버의 README에서 최신 명령을 확인하라 — 그걸 자동으로 하는 방법이 바로 다음 07번이다.

자동화context7로 최신 정보 조회 후 구성하는 프롬프트

MCP 설치 명령은 자주 바뀐다. 굳이 외우지 말고, context7으로 최신 문서를 먼저 조회한 뒤 그 결과로 설정을 만들게 Claude에게 시킨다. 아래 프롬프트를 그대로 붙여 넣고 <서버이름>만 바꾼다.

Claude Code에 붙여넣기
<서버이름> MCP를 이 프로젝트에 붙이고 싶어. 다음 순서로 해줘.

1. context7으로 "<서버이름> MCP server installation" 최신 문서를 조회해서
   - 정확한 실행 명령(npx 패키지명 또는 http url)
   - 필요한 환경변수/토큰
   을 먼저 확인해줘. 기억이 아니라 조회한 문서를 근거로 삼아.

2. 확인한 내용으로 .mcp.json 의 mcpServers 항목을 작성해줘.
   - 팀 공유가 목적이니 project 스코프(.mcp.json)로.
   - 토큰·키는 값에 직접 넣지 말고 ${ENV_VAR} 확장으로 빼줘.

3. 등록 후 확인 방법(claude mcp list / /mcp)과,
   내가 로컬에 채워야 할 환경변수 목록을 알려줘.

문서에서 명령을 못 찾으면 추측하지 말고 어디까지 확인됐는지 먼저 보고해줘.

이 프롬프트의 핵심은 3가지 제약이다. 이게 "그럴듯한 추측"을 막는다.

  • 근거 강제 — "기억이 아니라 조회한 문서" 한 줄이 오래된 학습 데이터로 명령을 지어내는 걸 막는다.
  • 비밀 분리 — ${ENV_VAR} 규칙을 미리 못 박아 토큰이 .mcp.json에 커밋되는 사고를 막는다.
  • 실패 보고 — 못 찾으면 추측 대신 멈추게 해, 틀린 설정을 커밋하는 것보다 낫게 만든다.
응용

같은 틀로 서버 여러 개를 한 번에 시킬 수 있다. <서버이름> 자리에 "context7, playwright, sequential-thinking"을 넣고 "셋 다 하나의 .mcp.json으로 합쳐줘"라고 덧붙이면 06번의 통합 설정을 문서 근거로 다시 만든다.

마무리점검 체크리스트 · 트러블슈팅

  1. 붙인 목적이 분명한가. "없으면 못 하는 일"이 있는 서버만 남겼는지 다시 본다.
  2. 스코프가 맞는가. 나만 쓰면 local, 팀 공유면 project(.mcp.json), 모든 프로젝트면 user.
  3. 비밀값이 파일에 없는가. .mcp.json에 토큰·키가 평문으로 박혀 있지 않은지 검사한다. ${ENV_VAR}로 뺐는지 확인.
  4. 연결되는가. claude mcp list → 상태 확인. 세션에서 /mcp → 도구가 실제로 보이는지 확인.
