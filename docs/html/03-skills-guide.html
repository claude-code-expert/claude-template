커맨드는 /이름으로 부른다. 스킬은 부르지 않는다 — 조건에 맞는 말을 하면 알아서 뜬다. 그 "조건"을 어디에 쓰느냐가 스킬의 전부다.

스킬(Skills) 가이드

강의 3편 · 대상 Claude Code 사용자 · .claude/skills/ 실제 코드 기준

개념스킬이란 무엇이고 커맨드와 뭐가 다른가

스킬(Skill)은 특정 종류의 작업이 시작될 때 Claude가 따라야 할 지침 묶음이다. 실체는 .claude/skills/<name>/SKILL.md 파일 하나이며, 필요하면 옆에 references/(상세 기준)와 scripts/(실제 계산·작업 스크립트)를 둔다.

핵심 차이는 호출 방식이다. 커맨드는 /git-commit처럼 이름을 쳐서 명시적으로 부른다. 스킬은 이름을 부르지 않는다. 조건에 맞는 발화가 나오면 자동으로 발동한다. 예컨대 "이 리포트 예쁘게 만들어줘"라고만 해도 anti-ai-slop이 알아서 걸린다.

커맨드스킬
호출/name 명시 호출발화 조건 충족 시 자동 발동
위치.claude/commands/*.md.claude/skills/<name>/SKILL.md
발동 스위치내가 이름을 침description에 쓴 트리거 문구
동반 자산단일 파일references/·scripts/ 동반 가능
쓰기 좋은 것매번 같은 정형 작업"이럴 때면 항상 이렇게" 류 판단·게이트

SKILL.md 구조

파일은 frontmatter(YAML 머리말)와 body로 나뉜다.

.claude/skills/<name>/SKILL.md
---
name: my-skill
description: 이 스킬이 "언제" 발동하는지. 트리거 발화 예를 여기 넣는다.
---

# 여기부터 body — 발동 후 Claude가 따르는 지침
- 무엇을 확인하고
- 어떤 순서로 처리하고
- references/ 의 어떤 파일을 언제 읽을지
  • name — 스킬 식별자. 보통 디렉터리명과 맞춘다.
  • description — 발동 트리거. Claude는 이 문장을 보고 "지금 이 스킬을 켤까"를 판단한다. 여기에 "언제 발동하는지"를 구체적으로 써야 자동으로 뜬다.
  • body — 발동 후 Claude가 실제로 따르는 지침.
  • references/ — 필요할 때만 읽는 상세 기준. body를 짧게 유지하고 무거운 판단표는 여기로 분리한다.
  • scripts/ — 실제 계산·작업을 하는 스크립트. 예: token-usage.py.
한 줄 요약

description = 언제 켜지나. body = 켜진 뒤 뭘 하나. 이 둘을 분리해서 생각하면 스킬 설계가 쉬워진다.

제작만드는 법 — 기능 지정 + 생성 프롬프트

스킬 하나를 만들 때 정할 것은 넷이다.

  1. 이름 — .claude/skills/<이름>/ 디렉터리와 SKILL.md의 name.
  2. 발동 조건(description) — 어떤 발화에 뜰지. 트리거 발화 예를 구체적으로 나열한다. 여기가 제일 중요하다.
  3. body 지침 — 발동 후 무엇을 어떤 순서로 할지.
  4. 분리 여부 — 세부 기준이 길면 references/로, 실제 계산이 필요하면 scripts/로 뺀다.
핵심 판단

description이 곧 발동 스위치다. 모호하면 안 뜨고, 너무 넓으면 오발동한다. "문서 잘 만들기"는 모호해서 안 걸리고, "무언가를 만들 때"는 넓어서 아무 데나 걸린다. 실제 사용자가 쓸 법한 발화 예 몇 개를 그대로 박아 넣는 것이 가장 잘 작동한다.

생성 프롬프트 템플릿

손으로 SKILL.md를 짜지 말고, 아래를 Claude에 붙여넣어 만들게 한다. <...>만 바꾼다.

Claude Code에 붙여넣기
.claude/skills/<이름>/SKILL.md 스킬을 만들어줘.

발동 조건: "<예: 이 리포트 예쁘게 만들어줘>", "<예: 슬라이드 만들어줘>"
  류의 발화. description 에 이런 트리거 발화 예를 그대로 넣어서
  자동으로 뜨게 해줘. 너무 넓게 잡아서 아무 데나 뜨지 않게 범위를 좁혀줘.

하는 일(body): <발동 후 따를 지침을 순서대로>

분리: 세부 기준이 길면 references/ 로 나눠주고,
  실제 계산·집계가 필요하면 scripts/ 로 스크립트를 빼줘.

이 템플릿의 포인트는 "description에 트리거 발화 예를 그대로 넣어라"와 "범위를 좁혀라" 두 문장이다. 이게 안 뜨는 스킬과 오발동하는 스킬을 동시에 막는다.

번들이 템플릿에 들어 있는 스킬 5종

레포의 .claude/skills/에 이미 5개가 들어 있다. 각각 name/description은 실제 파일 그대로다. 새 스킬을 만들 때 이 다섯 개가 좋은 견본이다.

anti-ai-slop — 시각·글쓰기 품질 게이트

.claude/skills/anti-ai-slop/SKILL.md — frontmatter
name: anti-ai-slop
description: 이미지·HTML·SVG·슬라이드·PDF 등 시각 산출물과 문서·리포트·카피 글쓰기를 생성·수정하기 전 반드시 발동한다. 그라데이션·글로우·장식 모션 등 AI 특유의 조악한(slop) 디자인을 차단하고, 상투어·균질 구조·불릿 남발 등 AI 티가 나는 글쓰기 흔적을 제거한다. 정보 위계·여백·타이포·근거·절제로 시니어 실무자가 만든 수준의 고급 산출물을 만드는 품질 게이트.

이미지·HTML·SVG·슬라이드·PDF 같은 시각 산출물과 문서·리포트·카피 글을 만들기 직전에 걸리는 게이트다. 그라데이션·글로우·장식 모션 같은 slop 디자인과, 상투어·균질한 문단 구조·불릿 남발 같은 AI 글쓰기 지문을 차단한다. 세부 기준은 references/의 visual-craft·slides-pdf·writing-tells 세 갈래로 분리돼 있어, 만드는 산출물 종류에 맞는 것만 읽는다.

발화 예: "이 리포트 예쁘게 만들어줘", "슬라이드/HTML 만들어줘" — 지금 이 페이지도 이 게이트를 거쳐 만들었다.

changelog — 되돌릴 수 없는 결정 기록

.claude/skills/changelog/SKILL.md — frontmatter
name: changelog
description: 되돌릴 수 없는 결정과 그 근거를 시간순으로 changelog/changelog.md에 기록한다. 아키텍처·의존성·API 계약 변경 시 사용. push/PR 직전 changelog-reminder 훅이 매니페스트 변경을 감지하면 이 스킬로 기록할지 검토한다.

아키텍처·의존성·API 계약처럼 나중에 "왜 이렇게 했지"가 나올 결정과 그 근거를 changelog/changelog.md에 append-only로 남긴다. 짝이 되는 changelog-reminder 훅이 push/PR 직전 매니페스트 변경을 감지하면 이 스킬로 기록할지 검토하게 밀어준다(훅은 강의 4편).

발화 예: "이 결정 기록해줘", 또는 의존성을 교체한 직후.

handoff — 세션 인계

.claude/skills/handoff/SKILL.md — frontmatter
name: handoff
description: 세션 인계. 컨텍스트가 차거나 세션을 끝낼 때 진행상황·결정·다음 할 일을 남겨 다음 세션이 이어가게 한다. "핸드오프", "이어서 작업", "인계/컨텍스트 정리", "세션 정리" 요청에 사용.

컨텍스트가 차거나 세션을 끝낼 때 진행상황·결정·다음 할 일을 .handoff.md(레포 루트)에 정리한다. precompact-handoff 훅이 압축 직전 남긴 기계적 스냅샷을, 사람이 읽을 인계문으로 다듬는 것도 이 스킬의 몫이다.

발화 예: "핸드오프", "이어서 작업", "세션 정리".

scaffold — 프로젝트 초기 구조 생성

.claude/skills/scaffold/SKILL.md — frontmatter
name: scaffold
description: 새 프로젝트나 하위 모듈의 초기 구조(스캐폴딩)를 만들 때 발동한다. "next.js/go/rust/java(spring)/typescript/react/vue 스캐폴딩 만들어줘", "프로젝트 초기 셋업", "보일러플레이트", "새 프로젝트 시작" 류의 발화에 반응한다. 공식 스캐폴더를 최신 명령으로 실행한 뒤 CLI가 안 만드는 구조·린터·CI를 얹는다.

손으로 템플릿을 찍지 않고 각 생태계의 공식 스캐폴더(create-next-app·cargo·create-vue·Spring Initializr 등)를 최신 명령으로 실행한 뒤, CLI가 만들지 않는 디렉터리 구조·린터·포매터·CI를 얹는다. CRA 같은 죽은 도구를 차단하고 YAGNI 구조를 강제한다. 세부는 references/의 js-ts·go-rust·java-spring로 분리.

발화 예: "next.js 스캐폴딩 만들어줘", "새 프로젝트 시작".

token-usage — 세션 토큰 집계

.claude/skills/token-usage/SKILL.md — frontmatter
name: token-usage
description: 현재/특정 세션의 토큰 사용량을 집계한다. "토큰 얼마나 사용", "토큰 측정", "토큰 사용량", "이번 세션 토큰", "token usage" 류 발화에 발동한다. input·output·cache creation/read를 나눠 보여주고 총합을 낸다.

세션 transcript의 토큰을 input·output·cache creation/read로 나눠 집계하고 총합을 낸다. 실제 계산은 body 지침이 아니라 동반 스크립트 .claude/scripts/token-usage.py가 한다 — scripts/를 동반하는 스킬의 대표 예다.

발화 예: "토큰 얼마나 썼어", "토큰 측정".

실행발화로 부르기 · 스크립트 동반 스킬 돌리기

스킬은 대개 발화만으로 자동 발동한다. 이름을 외울 필요가 없다. 아래는 이 5종의 대표 트리거 발화다.

스킬이런 말을 하면 뜬다
anti-ai-slop"이 리포트 예쁘게", "슬라이드/HTML 만들어줘"
changelog"이 결정 기록해줘", 의존성 교체 직후
handoff"핸드오프", "이어서 작업", "세션 정리"
scaffold"next.js 스캐폴딩 만들어줘", "새 프로젝트 시작"
token-usage"토큰 얼마나 썼어", "토큰 측정"

발동 후 흐름

스킬이 걸리면 Claude는 그 body 지침을 컨텍스트로 불러 그대로 따른다. body가 "이 경우엔 references/writing-tells.md를 봐라"라고 시키면, 필요한 순간에만 그 참조 파일을 읽는다. 이렇게 body는 얇게 두고 무거운 기준은 references로 미뤄, 안 쓸 때는 컨텍스트를 안 먹는다.

스크립트를 동반하는 스킬 — token-usage

token-usage처럼 실제 계산이 필요한 스킬은 발동 후 body가 동반 스크립트를 실행한다. 직접 돌려볼 수도 있다.

터미널 (레포 루트)
python3 .claude/scripts/token-usage.py            # 최신 세션 자동 탐색
python3 .claude/scripts/token-usage.py <파일.jsonl>  # 특정 세션 지정
요령

발화로 "토큰 얼마나 썼어"라고만 해도 스킬이 뜨고, 그 안에서 위 스크립트를 알아서 돌린다. 위 명령은 스킬 밖에서 직접 확인하고 싶을 때의 우회로다.

검증새 스킬이 실제로 발동하는지 테스트

스킬을 만들었으면 정말 뜨는지를 확인해야 한다. 방법은 단순하다 — 트리거에 해당하는 발화를 실제로 해보고 스킬이 걸리는지 본다.

  1. 트리거 발화를 그대로 쳐본다. description에 넣은 발화 예와 비슷한 문장을 Claude에 입력한다.
  2. 스킬이 뜨는지 확인한다. 해당 스킬이 발동해 body 지침대로 움직이면 성공이다.
  3. 안 뜨면 description을 보강한다. 트리거 문구를 더 구체적으로, 실제 쓸 법한 발화 예를 몇 개 더 박아 넣는다.
  4. 엉뚱하게 뜨면 범위를 좁힌다. 너무 넓은 표현을 걷어내고 조건을 명확히 한다.

증상별 조치

증상원인·조치
안 뜬다description이 모호하다. 트리거 문구를 구체화하고 실제 발화 예를 추가
엉뚱할 때 뜬다description 범위가 너무 넓다. 조건을 좁히고 과한 표현을 제거
스크립트 스킬이 계산을 안 함스크립트 경로와 python3 설치 확인. .claude/scripts/ 경로가 맞는지 점검
반복이 정상

한 번에 완벽한 description은 드물다. 발동 → 관찰 → description 조정을 두세 번 돌리면서 "뜰 때 뜨고, 안 뜰 때 안 뜨는" 지점을 찾는 게 정석이다.

스킬의 실체는 .claude/skills/<name>/SKILL.md 하나. description이 발동 스위치, body가 지침, references/·scripts/가 선택 자산이다.
